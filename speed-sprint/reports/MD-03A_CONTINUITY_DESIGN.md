## Findings and proposed minimum change

The middleware currently accepts nonempty identity/role headers as development stand-ins. That cannot establish an authenticated private-workspace owner. The checkpointer can fall back to MemorySaver when a configured durable backend package is absent; a professional save path must not silently downgrade durability. Current repository methods commit independently and do not implement an atomic learning-checkpoint aggregate. These are inspected source behaviors, not reproduced incidents in Robert's installation.

The current deliberation round requires an initial interpretation before reveal, while the teaching card excludes that private text. Therefore a future reopen should display the exact saved card and selected decision as a historical snapshot, not fabricate an earlier interpretation or relabel the old memory-only session. Revising begins a new comparison. Retained decision reasons may themselves be sensitive and must not inherit a public label from their sources.

The handoff proposes one owner-bound private checkpoint, using existing core and repository seams: deliberate preview and confirmation; exact action/policy/approval binding; unique pre-dispatch operation reservation and minimal audit; one bounded aggregate transaction; fresh authorized read-back; and an explicit unknown-outcome reconciliation path. Private initial interpretation, reflection, raw interview, SOUL and chat history are excluded by default. Content approval is neither implied by saving nor required from an educator for every ordinary private-draft save. Source admission remains separate.

SQLite is a proposed first local adapter, not an approved implementation. Initial platform, owner/session boundary, private-data classification, encryption/key management, backup/restore and deletion remain decisions for accountable review. No new schema, identity service, migration, store, native runtime, inference path or frontend save control was implemented.
