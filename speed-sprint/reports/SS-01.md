# Speed Sprint SS-01 — Make the mission portable

Status: implemented and tested within prototype scope; independent review pending; no merge or deployment.

## Human need and IoC mapping
A nurse should retain the same learning goal and inspectable professional record independently of the runtime, model or hosting arrangement. This increment supplies a synthetic, goal-identified mission and a responsive companion workspace. Primary pillar: Capability. Dependencies: Knowledge (source/limitation records), Judgment (understandable choices without authority), Contribution (portable attribution). Principal risk: polished metadata mistaken for completed learning or permission.

## Minimal implementation
Eleven additive files introduce canonical MissionRecord, DeploymentManifest and WorkspaceBundle contracts; a fixed synthetic learning goal; three inactive placement previews; responsive HTML; a reproducible snapshot builder; a loopback-only read server; acceptance RFC; tests; and a dedicated verification workflow. All 266 baseline tracked files remain byte-identical, including existing policies, schemas, CI and the seven held files.

The mission's ID, goal, source references and limitations are separate from deployment placement. Local, hybrid and hosted-test manifests distinguish interaction, harness, authoritative storage and inference. All enable flags must be false. Endpoint references are inert fixtures, not live URLs. Unknown fields/classifications/profiles, duplicate keys, non-finite or oversized JSON and copied invalid models are rejected.

The UI lets the nurse inspect the same nonempty record across placement previews. It labels the empty evidence pack and unfinished deliberation/saving. Its pause control pauses inspection only. There is no model, Hermes connection, user upload, private workspace, cloud service, clinical capability or portfolio save.
